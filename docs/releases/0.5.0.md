## Hot reload

- **`oh-my-http reload`** sends `SIGHUP`: accounts, UI language, lockout policy and directory bindings are
  re-read from the account file — no restart, no dropped connections. Handy after editing `users.json`.
- A broken account file is rejected and the old configuration keeps serving (the reason is logged);
  the `SIGHUP` handler is registered in `listen()` and removed on `close()`.

## Update notices in the admin panel

- Both admin pages now show a banner when a newer version exists (current → latest, the upgrade command and a
  release-notes link), in Chinese and English.
- “Check for updates” runs an on-demand registry lookup; opening the panel with a missing/24h-old cache
  triggers one background check (throttled to once per 10 minutes).

## Stopping leftovers & self-upgrade

- `stop` / `restart` / `reload` accept `--all` to handle every instance in the state directory.
- `stop --port <n>` now also works when the state file is gone: it finds the listening `oh-my-http` process
  via `lsof` and stops it (other programs are only reported, never killed).
- New `oh-my-http upgrade` (`--check`, `--force`, `--version <v>`, `--restart`) checks npm and runs
  `npm i -g oh-my-http@<version>` for you.
- Starting on an occupied port without a state file now prints an `lsof` hint instead of a bare `EADDRINUSE`.

## One-command release

- `npm run release -- <patch|minor|major|x.y.z>`: checks branch/dirty/ahead/tag, runs tests, renames the
  CHANGELOG “unreleased” heading, bumps both version files, tags and pushes — GitHub Actions then publishes.
  Supports `--dry-run`, `--skip-tests`, `--no-push`, `--allow-dirty`.

## Fixes

- Starting a second instance on the same port used to delete the running instance's state file first,
  making it invisible to `status` / `stop` / `restart`; it now refuses to start and keeps the state file.
- The reload notice used the access-log formatter and could crash the process (`durationMs` missing);
  non-access log entries are now formatted safely.

## 热加载

- **`oh-my-http reload`**：给运行中的实例发 `SIGHUP`，重新读取账号文件里的账号、界面语言、锁定策略和目录绑定，
  不重启、不断连接；手改过 `users.json` 之后不用再 `restart`。
- 账号文件写坏会拒绝加载并继续用旧配置（日志写明原因）；`SIGHUP` 处理器在 `listen()` 注册、`close()` 时摘掉。

## 后台新版本提示

- 「账号管理 / 目录绑定」页顶部新增升级横幅（当前 → 最新、升级命令、更新日志链接），中英文都有。
- 「立即检查更新」按需查 registry；打开后台时若缓存缺失或超过 24 小时会自动补查一次（10 分钟节流）。

## 停止残留进程与自升级

- `stop` / `restart` / `reload` 支持 `--all`，一次处理状态目录里的所有实例。
- `stop --port <n>` 在状态文件丢失时也能用 `lsof` 找到监听的 `oh-my-http` 进程并停掉；
  端口被其它程序占用时只警告、不动手。
- 新增 `oh-my-http upgrade`（`--check` / `--force` / `--version <v>` / `--restart`）：
  查 npm 最新版并执行 `npm i -g oh-my-http@<version>`。
- 端口被占用且没有状态文件时，启动会给出 `lsof` 排查提示，而不是只报 `EADDRINUSE`。

## 一条命令发版

- `npm run release -- <patch|minor|major|x.y.z>`：检查分支/工作区/落后远端/tag 重复 → 跑测试 →
  改 CHANGELOG「未发布」→ `npm version`（同步两处版本号）→ 打 tag → 推送，由 Actions 自动发布。
  支持 `--dry-run`、`--skip-tests`、`--no-push`、`--allow-dirty`。

## 修复

- 同端口重复启动会先删掉运行中实例的状态文件，导致它从 `status` / `stop` / `restart` 里消失；
  现在直接拒绝启动并保留状态文件。
- reload 提示曾复用访问日志格式、缺 `durationMs` 会崩进程；非访问日志现在安全输出。
